Colour

Surfaces and ink gy-shell.css :root

Warm neutrals. The page is never white: white is reserved for cards and fields so they lift off the background.

Rule--bg for the page, --card for anything raised, --graybg for a header row or an inset control.
Borders--line is the default hairline, --line2 is a control's own edge. A control hovers to --ink3, never to a brand colour.
Ink--ink for content, --ink2 for supporting text and labels, --ink3 for placeholders, units and things that are off.
NeverA page-level background other than --bg, and pure #000 or #FFF text.

Status colour

Four meanings only: good, attention, information, and the dark ink used for a primary action or a live state.

PairingEvery status colour ships as a background and a darker text tone (--greenbg with --greend). Text always takes the dark tone, never the raw hue.
GreenComplete, final, in good condition, an exact match.
AmberYou are needed: a decision or ask waiting on a person, plus partial, unallocated, overdue. Never the current step.
Current--cur, --curbg, --curd, --currow: where the work is right now (the current step, its Now label, its pip). Ink, not a hue, so it never competes with amber.
BlueInformational and links. A substitute match. Never success.
Yellow--yellow is the brand mark, used for the workspace tile and the unallocated card. It is not a status.

Ecosystem service tokens GY_ES

One token per service carries a colour, a background and an icon. Colour never carries identity alone, the icon is the second encoding, and the pair is validated for colour-blind separation.

DefinitionGY_ES[key] = {name, short, icon, cls} in gy-nav.js. The class sets --esc (the colour) and --esbg (its background).
Parts.es-tile 34px rounded square, .es-tile.sm 26px, .es-dot 9px square, .es-chip pill with icon and short name, .espill solid caps pill for a dense table.
Livebng, wcc and soc are in the data. nut and nfm are defined and unused, ready for a fourth and fifth service.
NeverA service drawn in a colour that is not its token, or a service shown as colour with no icon.

Layout and shape

The shell .shell / .snav / .mainc / .wrap

Every page is the same frame: a fixed rail, a sticky topbar carrying breadcrumbs, and one centred column.

Column.wrap{max-width:1080px;margin:0 auto;padding:36px 32px 100px}, dropping to 32px 22px 90px under 900px. Canonical on every shell page, no exceptions.
Rail264px, resizable by its grip, remembered in localStorage. Collapses to a 68px icon rail with a tooltip per icon; the GY tile expands it again (gyRail(), localStorage('gyRail')). A page with GYNAV.rail:true always opens on the rail and leaves the global choice alone; Deliverable pages use it. Rendered by gy-nav.js from window.GYNAV, never hand-written per page.
Topbar61px, sticky, translucent with a blur. Breadcrumbs come from the GY_CRUMB table in gy-nav.js, so altitude is consistent across pages.
Page header.phead: title left, action bar right, one hairline under the pair. Nothing else sits in that row.

Buttons

Primary, outline, quiet .btn-dark / .btn-out

Quiet link action
VariantsDark is the one thing this page is for, and there is never more than one. Outline is everything else. A link is for an action inside a row or a card that must not compete.
Anatomy10px radius, 9px by 15px padding, 14px text at weight 500, 7px gap to a 16px icon. Icon leads, label follows, both in sentence case.
StatesHover darkens the dark button to #2C1B22 and moves the outline border to --ink3. Focus is the browser ring. Disabled is 50% opacity and not clickable.
In the barThe action bar uses its own .abtn at the same rhythm. Do not mix .btn-out into a gyBar.
NeverTwo dark buttons in one view, a button whose label is a noun with no verb, or an icon-only button without a title.

Action bar

gyBar gyBar(host, cfg)

One bar per page, top right of the header. Both the bar at the top of this page and the one below are live, built by the same call every other page makes.

Inventory list
gyBar('abar', {
  search:  {placeholder:'Search documents', oninput:fn},   // or {onclick:fn}
  filters: [['Type', [['ti-circle-dot','All types','all'], …], {multi:true}]],
  buttons: [{icon:'ti-target-arrow', label:'Find units for buyer', onclick:fn}],
  actions: ROWS,                                     // rows for gyMenu
  primary: {icon:'ti-plus', label:'Add document', onclick:fn},
  onfilter: function(group, value){ … }
});
OrderFixed and not negotiable: Search, Filters, page buttons, Actions, primary. A page cannot reorder it, which is what keeps twenty pages recognisable.
SearchWith a placeholder it inserts its own field under .phead; with onclick it just calls that, for a page whose search is a drawer.
ButtonsPage tools that are neither a filter nor a write action, such as Settings or Find units for buyer.
ActionsSingle-shot write operations on this object, opened as a gyMenu. Never a read tool.
PrimaryThe one dark button. Usually Add.
Returns{filter, pop, clear(), set(group,value)}, so a stat card can drive a filter without poking the DOM.
NeverA second bar, a filter row under the title, or a button that duplicates an Actions row.

Filters

Filter groups cfg.filters

All page filtering happens in the bar. Open Filters below for the full case: six groups as an accordion, multi-select, in-group search, and four values behind Show all.

Six facets
['Habitat type', [
   ['ti-circle-dot', 'Any', 'any'],        // first option is the default AND the "any"
   ['ti-leaf', 'Lowland meadow', 'Lowland meadow'], …
 ], {multi:true, search:true, cap:4, open:false}]
DefaultThe first option is both the default and the group's "any". Selecting it clears the rest, and the badge counts groups that are off their first option, so a mis-ordered group shows a false count.
AccordionFour or more groups collapse to one open at a time, each shut header carrying its state: "Any", the value, or "2 selected". Three or fewer stay open and each header toggles only itself.
Long listsOver 8 values a group gains a search field and shows its first four behind Show all (N). Selected values survive both and pin under "any", so a choice never hides. cap:0 turns it off.
OrderingCommonest first, or a semantic rank where one exists (Available, Projected, Reserved, Sold). Alphabetical is the fallback, never the default.
DataOptions are built from the page's data, never typed by hand, so a filter cannot offer a value the page does not hold.
PlacementThe popup opens under the Filters button, measured at open time, and slides left only far enough to stay 12px inside the viewport. It is positioned against the window, not the bar, so a bar narrower than the popup cannot push it off screen.
ClearA Clear all footer appears as soon as anything is off default.
Not a filterA view switch (Sites vs Parcels) is a segmented control. A sort belongs to the column header. Neither goes in this popup.

Select field

gySel gy-select.js

The one dropdown field. A native select is never allowed: it cannot be styled, it breaks the warm palette, and it renders differently on every platform.

gySel('q-lpa', {
  options: [['val','Label'], …] || function(){ return […]; },
  value: cur, placeholder: 'Any LPA', width: '100%',
  onchange: function(v){ … }
});
AnatomyButton 10px radius, 1px #DED8CA border, 9 by 11px padding, 13.5px label, chevron drawn in CSS. The popup is fixed, min 232px, max 340px tall, scrolling.
StatesPlaceholder in --ink3, hover and open border #A79E8D, selected row bold with a tick.
OptionsA plain list, a [value,label] pair list, or a function evaluated at open time, which is how a field re-reads the data after another field changes it.
LabelsA field that needs explaining gets a .flab label above it with gyInfo beside it. The label is display:flex;align-items:center so the i sits on its centre line.
GotchaThe popup opens at z-index 1600 so it clears a drawer. Its outside-click handler is one stable listener, unbound at the top of close.

Segmented control

View switch .seg

Changes what a row is, not which rows show. That distinction is the whole reason it exists beside the filter popup.

AnatomyA --graybg track at 11px radius with 3px padding; the selected button is white at 8px radius with the 1px raised shadow and weight 500.
LabelsCarry the count in the label (Sites · 7). A switch that tells you the size of each view earns its line.
PlacementDirectly under the page header, left aligned, alone on its line.
NeverUsed for filtering, and never more than four options. Beyond that it is a filter group.

Tooltip

gyInfo and the tooltip layer gyInfo(tip) · [data-tip]

Hover either i below. The bubble is painted by one fixed layer on the body, so a drawer or a scrolling table cannot clip it.

TriggerAny element carrying data-tip, on hover and on keyboard focus. gyInfo(tip) renders the standard 15px i.
PlacementAbove the element, flipped below when there is no room, clamped 8px inside the viewport.
DismissMouseout, blur, scroll, resize, Escape. Only one exists at a time.
ContentA definition or a fact about the data. Never a description of the interface: "Owner is read only here" is filler, "the LPA the development sits in" is a definition.
Exceptions.sav on canvases and .info on the market map paint their own bubbles and are skipped, so nothing shows two.
NeverA ::after tooltip inside a scrolling container. It gets clipped, which is exactly the bug this layer replaced.

State chip

gyChip gyChip(text, tip, state)

Live state beside a page title. This is the one thing allowed next to a heading, because it carries a fact rather than a description.

StatesThe dot carries the state: '' fresh (green), 'warn' (amber), 'bad' (red), 'idle' (grey). Text stays --ink2 in all four.
BehaviourFocusable, and its tooltip underlines on hover. Sized 13.5px so it reads beside a serif title without competing with it.
ContentA fact about the data: source, last sync, record id, saved or not. Its tooltip may add detail, still factual.
NeverA descriptive subtitle in chip clothing. See the rules below.

The prototype's stand-in for work that is not built, and the confirmation for work that is.

Checkbox

The house checkbox input[type="checkbox"]

Styled on the element itself in gy-nav.js, so every list, filter and toggle matches without a page opting in. The boxes below are plain inputs with nothing added.

<input type="checkbox">                    // the whole API

gySelAll(el, total, selected);            // drives the header box's three states
Anatomy16px square, 1.5px #B4B2A9 edge, 4px radius, white fill. Checked and indeterminate both fill Capital blue #185FA5, the mark in white: a rotated tick, or a 8 by 2px bar.

Principles

What the v8 Deliverable page settled on 3 Oct 2026. The rules below say what never to do; these say what good looks like.

Shell and navigation

Collapse to a rail, never to nothing

The sidebar folds to an icon rail so every destination stays one click away. Deliverable pages open on the rail so the work gets the room.

One toggle, one home

The sidebar toggle sits in front of the breadcrumb and handles both directions. The GY logo is always Home.

The chrome never moves

Same 61px topbar, same full breadcrumb, same alignment on every page. A page's own content never stretches it.

Visual refinement

Refine by scaling down

Smaller badges, tighter rows, medium weight instead of bold. Calm beats loud.

Icons stand alone

No tinted box behind a list or title icon. Drop the box and give the glyph the size instead.

One generous padding

Content sits in one even inset, 60px inside the document card, on every tab.

Active by colour, not weight

Mark the current item with ink and a bar. A change in weight changes width, and a list that rewraps on click jumps.

Colour carries one meaning

Ink means current

Where the work is right now: the current step, its Now label, its pip. Tokens --cur, --curbg, --currow.

Amber means a person is needed

A decision or an ask waiting on someone. Nothing else uses it.

Content and states

Empty states preview the final shape

Show the real table, card or box with bars for text. Where the content is not known yet, keep it generic.

Say it once

Cut anything that repeats what the page already says elsewhere.

Let the data write the UI

Counts and roles come from the workflow, not from typed copy, so they stay true when the steps change.

Settings header

Settings is the run's configuration

Agents, skills, knowledge, connectors, tools, inputs and outputs for this one run of a blueprint.

The header sets expectations

The blueprint leads, then what the run is for, then who does what. Project facts drop to a quiet context line.

Less is more

A summary that restates the page reads as clutter. Leave it out.

Rules that are not components

A shared component's styles ship with its JS

gy-nav.js writes its stylesheet into the body, so it beats a page's own head CSS on document order. Never fix a shared component by editing one page's style block: that is how the rail drifted across thirty files.

The data lives in the gy-*.js files

gy-todos, gy-projects, gy-sites, gy-calendar, gy-inventory, gy-docs, gy-deals and gy-search own their lists. Pages render from them and never retype a row, which is why two surfaces cannot show different numbers for the same thing.

Filtering lives in the action bar

No chip rows, no segmented filters, no bespoke dropdown. A view switch and a sort are not filters.

A row is one line

No subtitle under a name in any list or table. Extra facts become a column or an inline chip.

No subtitle beside a page title, and no instructional filler

The interface does not explain itself in prose. A state chip and a field tooltip are the sanctioned exceptions, and both carry facts.

Never a native select

gySel everywhere, including inside drawers and canvases. Zero native selects prototype-wide.

Breadcrumbs come from the crumb table

GY_CRUMB in gy-nav.js owns altitude (Portfolio › workspace › bucket › page). A page never writes its own trail.

Write actions scatter onto their object

There is no Manage hub. Multi-step and document-producing work is a Workflow, a single-shot change across rows is an Actions row, one row at a time is a row action.

Anything floating goes in a layer on the body

Menus, field popups and tooltips are appended to the body and positioned fixed. A popover built inside a scrolling parent gets clipped, every time.

One stable outside-click listener

Every popover binds one named handler, ignores clicks inside itself, and removes the listener unconditionally when it closes. The per-open closure version made every menu and field on a page work exactly once.
